# Employee-Level Risk Governance Policy

**Platform:** Adaptive Workforce Intelligence (AWI)  
**Phase:** 14  
**Status:** Active  
**Jurisdiction:** Kingdom of Saudi Arabia (PDPL)

---

## 1. Purpose

This document defines the governance rules that apply to all employee-level risk scoring operations within AWI. These rules are mandatory and technically enforced — they cannot be overridden by configuration.

---

## 2. What Employee-Level Scores Are

Employee-level risk scores in AWI are **statistical risk indicators** derived from aggregated HR construct signals. They are:

| ✅ What they are | ❌ What they are NOT |
|---|---|
| Probabilistic risk indicators | Deterministic resignation predictions |
| HR-review support tools | Automated employment decisions |
| Organisational signal aggregations | Individual psychological assessments |
| Data-driven conversation starters | Grounds for termination or demotion |
| Anonymous record scores | Personal identification instruments |

---

## 3. Mandatory Governance Rules

### 3.1 No PII in Output

The following categories of data are **never** included in scored output, exports, or API responses:

- Full name or partial name
- National ID (Iqama, Passport)
- IBAN or bank account number
- Phone or mobile number
- Email address
- Date of birth
- Home address
- Biometric data
- Photos

All these columns are stripped before any scoring computation begins.

### 3.2 Masked Employee Identifiers

If an `employee_id` / `employee_number` column is present in the uploaded dataset, AWI applies a **one-way cryptographic hash** (SHA-256, first 6 hex digits) to produce a safe display token:

```
Raw:    EID-0042
Masked: EMP-A3F91C
```

If no employee identifier exists, sequential safe IDs are assigned:

```
EMP-0001, EMP-0002, EMP-0003, …
```

The mapping between masked IDs and real employee identifiers is **never stored** by AWI.

### 3.3 Non-Deterministic Language Mandate

All user-facing text generated by the scoring engine must use non-deterministic language:

| ✅ Permitted language | ❌ Forbidden language |
|---|---|
| "Risk indicator" | "Will resign" |
| "Stability score" | "Guaranteed attrition" |
| "Priority review" | "Fire / replace this employee" |
| "Requires HR review" | "Psychological diagnosis" |
| "Organisational risk signal" | "Certain to leave" |

This is enforced in `employee_risk_scoring.py` and verified by the Phase 14 test suite.

### 3.4 HR Professional Review Requirement

AWI scores **must** be reviewed by a qualified HR professional before any workforce action is taken. The platform:

- Displays this requirement in every score card
- Includes it in every CSV export header
- Shows it in every individual employee profile drawer

### 3.5 No Individual Employment Decisions

Scores may not be used as the sole basis for:

- Termination or layoff
- Demotion
- Salary reduction
- Performance improvement plans
- Promotion denial

## 4. Data Flow and Isolation

```
Upload (HTTPS POST, local only)
  ↓
Saudi HR Column Normalisation
  ↓
SecureFileIngestion Governance Scan (PII/leakage detection)
  ↓
EmployeeRiskScorer (PII columns stripped, IDs masked)
  ↓
Scored records in memory (never persisted server-side)
  ↓
JSON response → Frontend localStorage (browser-only)
  ↓
CSV Export (governance disclaimer header required)
```

**No employee data is ever stored on the server.**  
**All processing is local and offline.**

## 5. PDPL Alignment

| PDPL Requirement | AWI Implementation |
|---|---|
| Purpose Limitation | Scores used only for HR workforce stability review |
| Data Minimisation | PII columns stripped before scoring |
| Data Subject Protection | No individual identifiers in output |
| Processing Accountability | Governance disclaimer on all exports |
| Security Measures | Local-only processing, no cloud transmission |

---

## 6. Technical Enforcement

These governance rules are technically enforced at the following layers:

1. **`EmployeeRiskScorer._sanitize_df()`** — strips PII columns before any computation
2. **`EmployeeRiskScorer._make_record_id()`** — SHA-256 hash masks employee identifiers
3. **`export_employee_risk_csv()`** — mandatory disclaimer header on all CSV exports
4. **`validate_export_safety()`** — post-export scan for email/phone/IBAN patterns
5. **Phase 14 test suite** — 20 tests covering all governance rules
